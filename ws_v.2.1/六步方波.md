# Six-Step Block Commutation Architecture

## Overview

BLDC six-step trapezoidal commutation with Hall sensor feedback, supporting open-loop forced drive, flying-start transition, and closed-loop Hall-synchronized operation. PWM generated by HC32F460 TMR4 unit 3, six outputs on PB4~PB9 via SDH21263 pre-driver.

## Hardware

| Component | Detail |
|---|---|
| MCU | HC32F460 (Cortex-M4, 200 MHz) |
| Gate Driver | SDH21263 (per phase: H,H=high-side ON, L,L=low-side ON, H≠L=interlock OFF) |
| Timer | TMR4 unit 3 (CM_TMR4_3), 50 kHz center-aligned triangle wave |
| PWM Pins | PB9(UH), PB8(UL), PB7(VH), PB6(VL), PB5(WH), PB4(WL) — all GPIO func2 |
| Hall Pins | PA10(Hall U), PA9(Hall V), PA8(Hall W) |
| Motor | 3 pole pairs, 3000 RPM max |

## PWM Layer: `tmr4_pwm.c/h`

Three half-bridge channels (U/V/W), each independently configurable at runtime:

| Mode | Hardware Config | H/L Behavior | SDH21263 Result |
|---|---|---|---|
| `SYNC` (through) | THROUGH PWM, both OC enabled | H and L output identical waveform | H=L → HIGH=upper ON, LOW=lower ON |
| `COMPLEMENTARY` | DEAD_TMR PWM, only low-side OC | H hardware-complement of L (with dead-time) | H≠L → interlock → both FETs OFF |

**Key functions:**
- `TMR4_PWM_Config(cfg)` — GPIO init + counter (triangle) + 3 channels OC/PWM with per-channel mode
- `TMR4_PWM_SetChannelMode(ch, mode, duty)` — Runtime mode switch (SYNC ↔ COMPLEMENTARY)
- `TMR4_PWM_SetDuty(ch, duty)` / `SetDutyFloat(ch, pct)` — Duty cycle update
- `TMR4_PWM_StartOutput()` / `StopOutput()` / `EmergencyStop()`
- `TMR4_PWM_SetFrequency(hz)` — Runtime frequency change

**Shadow registers:** All duty/mode writes go to shadow registers, transferred at counter PEAK for glitch-free 3-channel sync.

```
                  │ (Hall ISR)   │
                  └──────────────┘
```

## Mode Details

| Mode | Enum | Description |
|------|------|-------------|
| 0 | `COMM_RUNNER_STOP` | All phases complementary OFF, 98% SYNC (high-side brake) |
| 1 | `COMM_RUNNER_OPEN_FW` | Open-loop forward, linear ramp to constant step interval |
| 2 | `COMM_RUNNER_OPEN_RV` | Open-loop reverse, linear ramp to constant step interval |
| 3 | `COMM_RUNNER_CLOSED_FW` | Open-loop ramp → flying start → closed-loop forward |
| 4 | `COMM_RUNNER_CLOSED_RV` | Open-loop ramp → flying start → closed-loop reverse |

Mode 3/4 use a `comm_sub_phase` state machine:
- **Phase 0**: Open-loop forced commutation with linear ramp over `OL_RAMP_DURATION_MS` (2000ms). Interval ramps from `OL_START_INTERVAL_US` (~167 RPM) to `OL_TARGET_INTERVAL_US` (~1111 RPM).
- **Phase 1**: Ramp complete → `hall_3ch_start_flying()` reads current Hall GPIOs, looks up commutation step, sets `last_step`, and enters RUNNING directly — **no alignment, no coast**. The Hall ISR takes over seamlessly.

## Commutation Step Table

Each of the 6 steps maps 3 phases to a drive pattern:

| Step | Macro | U-phase | V-phase | W-phase | Current Path |
|------|-------|---------|---------|---------|-------------|
| 0 | `UH_VL` | PWM (SYNC, duty) | ON (SYNC, 2%) | OFF (COMP, 50%) | U→V |
| 1 | `UH_WL` | PWM (SYNC, duty) | OFF (COMP, 50%) | ON (SYNC, 2%) | U→W |
| 2 | `VH_WL` | OFF (COMP, 50%) | PWM (SYNC, duty) | ON (SYNC, 2%) | V→W |
| 3 | `VH_UL` | ON (SYNC, 2%) | PWM (SYNC, duty) | OFF (COMP, 50%) | V→U |
| 4 | `WH_UL` | ON (SYNC, 2%) | OFF (COMP, 50%) | PWM (SYNC, duty) | W→U |
| 5 | `WH_VL` | OFF (COMP, 50%) | ON (SYNC, 2%) | PWM (SYNC, duty) | W→V |

- **SYNC(duty%):** H=L, both follow duty cycle → active phase (PWM high-side or ON low-side)
- **SYNC(2%):** Nearly always LOW → low-side ON (return path)
- **COMP(50%):** H≠L → interlock → floating phase (both FETs OFF)

## PWM Duty vs Motor Behavior

- **Driving step (SYNC, duty%):** H=L, upper FET conducts `duty%` of time → PWM torque
- **Return step (SYNC, 2%):** Nearly always LOW → lower FET conducts → GND return
- **OFF step (COMP, 50%):** H≠L → interlock → floating (both FETs off)
- **Coast (SYNC, 98%):** All 3 phases near-HIGH → all upper FETs → same potential → no current
- **Brake (SYNC, 2% on all):** Not implemented — would short all windings to GND via lower FETs

## Per-Channel Optimization

`Commutation_Step` tracks per-channel mode and duty to avoid redundant register writes:

```
For each channel (U, V, W):
  if   mode changed (SYNC ↔ COMP) → TMR4_PWM_SetChannelMode  (full reinit, ~100 reg writes)
  elif duty changed (D_PWM only)  → TMR4_PWM_SetDutyFloat     (OCCR only, ~10 reg writes)
  else                            → skip                      (0 writes)
```

Typical step change only affects 2 channels (1 mode change, 1 duty change), saving ~70% of register writes compared to full 3-channel reinit.

## Hall Sensor ISR Flow

Three Hall sensors on GPIO EXINT (both edges): PA10(Hall U, INT009), PA9(Hall V, INT010), PA8(Hall W, INT008).

```
EXTINT trigger (both-edge, HW filter DIV64 ~1.56 MHz)
  │
  ├─ Read Hall GPIO ×2 with ~0.5 µs gap
  │  └─ Samples differ → PWM glitch → discard
  │
  ├─ State unchanged from last_hall_state → discard
  │
  ├─ Lookup hall_to_step[state]
  │  └─ step == 0xFF (000/111) → fault → set s_fault_pending
  │
  ├─ Valid step → direction check (diff == 1 → FW, diff == 5 → RV)
  │  └─ Invalid jump → discard, do NOT corrupt last_step
  │
  └─ NOW call GetDelta() → interval check (>50 µs) → record pulse
     └─ on_step callback → Commutation_Step
```

### Critical Design Decision: GetDelta() Called Late

`Timer6_Timebase_GetDelta()` resets its internal counter on every call. If called during a noise event that is later rejected, the counter is reset and the NEXT legitimate transition measures from the noise event — causing a false short interval and incorrect RPM.

By placing `GetDelta()` AFTER all structural checks, noise events never reset the counter. The interval always measures from the last VALID pulse.

### Multi-Sample Debounce

PWM switching noise can couple onto Hall lines and cause false EXTINT triggers. Two layers of defense:

**Layer 1 — Hardware filter**: EXTINT filter ON with DIV64. PCLK1/64 ≈ 1.56 MHz sampling rate. Rejects glitches shorter than ~10 µs.

**Layer 2 — Software double-sample**: After EXTINT fires, read all 3 GPIOs twice with ~0.5 µs gap (100 NOPs @ 200 MHz). If the two reads disagree, the trigger is a PWM glitch → discard immediately without calling `GetDelta()`.

```
hall_common_handler (ISR):
  1. read_hall_state_raw()  → state1
  2. delay ~0.5 µs
  3. read_hall_state_raw()  → state2
  4. state1 != state2 → return  (PWM glitch)
  5. state == last_hall_state → return  (no change)
  6. hall_to_step[state] == 0xFF → fault (000/111)
  7. direction check: diff != 1 and diff != 5 → return  (invalid jump, don't update last_step)
  8. NOW call GetDelta()  ← only valid transitions reach here
  9. interval < 50 µs → return  (too fast, noise)
 10. record pulse: interval, timestamp, pulse_counter++
 11. direction confirmation (3 consistent samples)
 12. on_step callback → Commutation_Step
```

### Hall State Sequence

Measured by hand-turning motor clockwise and confirmed by open-loop rotation:

```
CW Hall order:  0x03 → 0x02 → 0x06 → 0x04 → 0x05 → 0x01 → 0x03
CCW Hall order: 0x03 → 0x01 → 0x05 → 0x04 → 0x06 → 0x02 → 0x03  (reverse of CW)
```

State code formation: `(PA10 << 2) | (PA9 << 1) | PA8`

### Correct Hall-to-Step Mapping (Table 12)

Derived from open-loop CW test data. The commutation step DECREASES during CW rotation (0→5→4→3→2→1→0).

```
Hall State  →  Commutation Step
  0x03 (011) →  0  (UH_VL)
  0x02 (010) →  5  (WH_VL)
  0x06 (110) →  4  (WH_UL)
  0x04 (100) →  3  (VH_UL)
  0x05 (101) →  2  (VH_WL)
  0x01 (001) →  1  (UH_WL)
```

Table array: `{0xFF, 1, 5, 0, 3, 2, 4, 0xFF}` — invalid states 0x00 (0b000) and 0x07 (0b111) map to 0xFF (fault).

### Direction Detection

```
diff = (current_step - last_step + 6) % 6

diff == 1 → tentative = FORWARD
diff == 5 → tentative = REVERSE
otherwise → invalid jump, return (do NOT update last_step)
```

Direction is confirmed after `DIR_CONFIRM_COUNT` (3) consecutive consistent direction samples. On invalid jumps, `last_step` is NOT updated — this prevents PWM noise from corrupting the tracking state.

## RPM Calculation: M-Method (Pulse Accumulation)

Fixed time-window pulse counting instead of per-pulse interval measurement:

```
hall_3ch_update (called from CommRunner_Update, ~1 kHz):

  // Accumulate pulses since last call
  delta = pulse_counter - last_pulse_count
  accum_pulses += delta
  last_pulse_count = pulse_counter

  // Two trigger conditions:
  if accum_pulses >= 6 AND elapsed >= 20 ms:
      → High-speed accurate update (at least 1 electrical revolution)
      RPM = accum × 60,000,000 / (elapsed × pole_pairs × 6)
      push to sliding-window filter (6 samples)
      reset accum + timer

  if elapsed >= 500 ms AND accum_pulses > 0:
      → Low-speed forced update (enough time, whatever pulses we have)
      RPM = accum × 60,000,000 / (elapsed × pole_pairs × 6)
      push to sliding-window filter
      reset accum + timer

  if elapsed >= 500 ms AND accum_pulses == 0:
      → Motor stopped
      RPM = 0, push to filter, reset accum + timer
```

### RPM Formula

```
RPM = pulses × 60,000,000 / (dt_microseconds × pole_pairs × 6)

Where:
  pulses         = accumulated hall transitions in the window
  dt_microseconds = elapsed time since last RPM update
  pole_pairs      = motor pole pairs (configurable, default 3)
  6               = steps per electrical revolution
  60,000,000      = microseconds per minute
```

| | T-Method (old) | M-Method (new) |
|---|---|---|
| Noise immunity | 1 fake pulse → RPM spike | diluted across N pulses |
| Update rate | every pulse | every ~20 ms (batch) |
| Low-speed accuracy | good (per-pulse) | good (>1 pulse per 500 ms) |

## Hall Tables

16 tables × 8 entries each (hall state 0x00~0x07 → step 0~5 or 0xFF invalid), stored in `hall_tables[16][8]`:

| Index | Purpose |
|-------|---------|
| 0~5 | Synchronous (hall+1 = magnetic field CW), offset 0~5 steps |
| 6~11 | Offset (hall+1 = magnetic field CCW), offset 0~5 steps |
| 12 | Empirically corrected CW table from open-loop test data |
| 13 | Empirically corrected CCW table (opposite of 12) |
| **14** | **Lead-angle forward** (sector+90° voltage vector) — **default CW** |
| **15** | **Lead-angle reverse** (sector-90° voltage vector) — **default CCW** |

Both `hall_table_cw` and `hall_table_ccw` indices are independently adjustable in Keil Watch without recompiling.

## Flying Start

`hall_3ch_start_flying()` reads the current Hall state via double-sample, maps to step via table, and immediately enters `STATE_RUNNING` without alignment. This allows seamless transition from open-loop forced drive to closed-loop Hall-synchronized commutation.

```
hall_3ch_start_flying:
  1. read_hall_state_raw() → h1
  2. delay ~0.5 µs (100 NOPs)
  3. read_hall_state_raw() → h2
  4. h1 != h2 → fallback to state 0x00
  5. step = hall_to_step[hall_state]
  6. step == 0xFF → fallback to step 0
  7. state = STATE_RUNNING, last_step = step
  8. call on_step callback → immediate first commutation
```

## Stall Detection

In `hall_3ch_update`, if `last_pulse_time_us` exceeds `stall_timeout_ms` (default 500 ms) since the last valid Hall pulse, the motor is flagged as stalled and commutated to STOP.

## Key Constraints

- **GBK encoding:** All `.c`/`.h` files use GBK. Use `iconv -f GBK -t UTF-8` before editing, convert back after.
- **TMR4 unit:** CM_TMR4_3 on PCLK1 (100 MHz). Period = PCLK1 / (freq × 2) for center-aligned.
- **ISR timing:** `hall_common_handler` runs in EXINT ISR context. Keep it short — reads GPIO, does table lookup, calls `on_step` which calls `Commutation_Step`.
- **Flash erase/write cycles** are limited (~10K-100K). Each `Param_Save()` triggers a sector erase. Avoid calling it per-register in multi-register writes — the batch write path calls `Param_Save()` once for the entire batch.

## Troubleshooting: Closed-Loop Oscillation at Specific Speeds

### Symptom

Motor oscillates violently at ~1800 RPM in closed-loop, but occasionally breaks through and runs smoothly at ~3000 RPM.

### Root Cause: Fixed Advance Angle Mismatch

Hall-sensor commutation relies on a mapping table that converts Hall state (3-bit GPIO) to commutation step (0–5). The default closed-loop uses **table 14**, which applies a fixed **+90° electrical advance**:

```
hall_tables[14] = {0xFF, 2, 0, 1, 4, 3, 5, 0xFF}   // sector+90° (forced forward)
```

The optimal advance angle is **speed-dependent**, not constant:

| Speed | Current rise time vs. commutation period | 90° advance |
|-------|------------------------------------------|-------------|
| Low (~1800 RPM) | Current rises fast relative to period | **Over-advanced** → torque ripple → oscillation |
| High (~3000 RPM) | Current rise time takes significant portion of period | Near optimal → smooth |

At low speed, excessive advance causes the stator field to jump too far ahead of the rotor. The rotor catches up with a torque spike, overshoots, and the cycle repeats — producing violent 6× electrical frequency vibration (~180 Hz at 1800 RPM with 3 pole pairs).

### Why PID Won't Fix This

This is **torque ripple within each commutation cycle**, not average speed drift:

```
Wrong advance → torque shock every 60° electrical → 6×ef vibration
                     ↑
            PID only adjusts duty once per speed loop (~20 ms),
            far too slow for 180 Hz vibration.
            Worse: PID may oscillate trying to compensate.
```

| | Commutation Jitter | Speed Regulation |
|---|---|---|
| Root cause | Advance angle mismatch | Load/voltage variation |
| Frequency | 6× electrical (e.g. 180 Hz) | Low (< 10 Hz) |
| PID relevant? | **No** | Yes |
| Fix | Correct Hall table / dynamic advance | PID speed loop |

### Correct Fix Path

**Step 1 — Find the right table** (experiment in Keil Watch):

| Table | Advance | Expected Behavior |
|-------|---------|-------------------|
| 0 | 0° (synchronous) | Smooth at low speed, may lack torque at high speed |
| 1 | +60° electrical | Moderate advance |
| 2 | +120° electrical | High advance |
| 3 | +180° electrical | Maximum advance |
| 12 | Measured calibration | Based on actual Hall mounting offset |
| **14** (current) | +90° forced | Good at high speed, oscillates at low speed |

Procedure: pause debugger → change `hall_table_cw` in Keil Watch → resume → observe at multiple speeds.

**Step 2 — Dynamic advance switching** (if no single table works across full speed range):

```c
if (RPM < 2000)  hall_table_cw = 0;   // zero advance, smooth low-speed
if (RPM >= 2000) hall_table_cw = 14;  // 90° advance, efficient high-speed
```

Or linear interpolation between two tables based on RPM.

**Step 3 — Add PID speed loop** (only after commutation is smooth across the full range).
A PID controller regulates average speed by adjusting duty cycle. It cannot fix per-cycle torque ripple from incorrect commutation timing.
