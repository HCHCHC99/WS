# Six-Step Block Commutation Architecture

## Overview

BLDC six-step trapezoidal commutation with Hall sensor feedback, supporting open-loop forced drive, flying-start transition, and closed-loop Hall-synchronized operation. PWM generated by HC32F460 TMR4 unit 3, six outputs on PB4~PB9 via SDH21263 pre-driver.

## Mode Details

| Mode | Enum | Description |
|------|------|-------------|
| 0 | `COMM_RUNNER_STOP` | All phases complementary OFF, 98% SYNC (high-side brake) |
| 1 | `COMM_RUNNER_OPEN_FW` | Open-loop forward, linear ramp to constant step interval |
| 2 | `COMM_RUNNER_OPEN_RV` | Open-loop reverse, linear ramp to constant step interval |
| 3 | `COMM_RUNNER_CLOSED_FW` | Open-loop ramp → flying start → closed-loop forward |
| 4 | `COMM_RUNNER_CLOSED_RV` | Open-loop ramp → flying start → closed-loop reverse |

## Commutation Step Table

Each of the 6 steps maps 3 phases to a drive pattern:

| Step | Macro | U-phase | V-phase | W-phase |
|------|-------|---------|---------|---------|
| 0 | `UH_VL` | PWM (SYNC, duty) | ON (SYNC, 2%) | OFF (COMP, 50%) |
| 1 | `UH_WL` | PWM (SYNC, duty) | OFF (COMP, 50%) | ON (SYNC, 2%) |
| 2 | `VH_WL` | OFF (COMP, 50%) | PWM (SYNC, duty) | ON (SYNC, 2%) |
| 3 | `VH_UL` | ON (SYNC, 2%) | PWM (SYNC, duty) | OFF (COMP, 50%) |
| 4 | `WH_UL` | ON (SYNC, 2%) | OFF (COMP, 50%) | PWM (SYNC, duty) |
| 5 | `WH_VL` | OFF (COMP, 50%) | ON (SYNC, 2%) | PWM (SYNC, duty) |

- **SYNC mode**: both H/L outputs follow same duty, used for PWM-driving and low-side ON phases.
- **COMPLEMENTARY mode**: dead-timer auto-generates H from L, both at 50% → interlock OFF.
- Pre-driver truth table (SDH21263): H,H → high ON; L,L → low ON; H≠L → OFF.

## Per-Channel Optimization

`Commutation_Step` tracks per-channel mode and duty to avoid redundant register writes:

```
For each channel (U, V, W):
  if   mode changed (SYNC ↔ COMP) → TMR4_PWM_SetChannelMode  (full reinit, ~100 reg writes)
  elif duty changed (D_PWM only)  → TMR4_PWM_SetDutyFloat     (OCCR only, ~10 reg writes)
  else                            → skip                      (0 writes)
```

Typical step change only affects 2 channels (1 mode change, 1 duty change), saving ~70% of register writes compared to full 3-channel reinit.

## Hall Sensor ISR Flow

```
EXTINT trigger (both-edge, HW filter DIV64 ~1.56 MHz)
  │
  ├─ Read Hall GPIO ×2 with ~0.5 µs gap
  │  └─ Samples differ → PWM glitch → discard
  │
  ├─ State unchanged from last_hall_state → discard
  │
  ├─ Lookup hall_to_step[state]
  │  └─ step == 0xFF (000/111) → fault → set s_fault_pending
  │
  ├─ Valid step → direction check (diff == 1 → FW, diff == 5 → RV)
  │  └─ Invalid jump → discard, do NOT corrupt last_step
  │
  └─ NOW call GetDelta() → interval check (>50 µs) → record pulse
     └─ on_step callback → Commutation_Step
```

Key: `GetDelta()` is called only AFTER all structural checks pass. Noise events that fail early never reset the delta counter, so the next valid pulse always measures from the last valid pulse.

## RPM Calculation: M-Method

Fixed time-window pulse counting instead of per-pulse interval measurement:

```
hall_3ch_update (called from CommRunner_Update at ~1 kHz):
  delta_pulses = pulse_counter - last_pulse_count
  accum_pulses += delta_pulses

  if accum_pulses >= 6 AND elapsed >= 20 ms:
      RPM = accum_pulses × 60,000,000 / (elapsed × pole_pairs × 6)
      apply sliding-window average filter (6 samples)
      reset accum

  if elapsed >= 500 ms AND accum_pulses == 0:
      RPM → 0  (motor stopped)
```

| | T-Method (old) | M-Method (new) |
|---|---|---|
| Noise immunity | 1 fake pulse → RPM spike | diluted across N pulses |
| Update rate | every pulse | every ~20 ms (batch) |
| Low-speed accuracy | good (per-pulse) | good (>1 pulse per 500 ms) |

## Hall Tables

16 tables × 8 entries each (hall state 0x00~0x07 → step 0~5 or 0xFF invalid):

| Index | Purpose |
|-------|---------|
| 0~5 | Synchronous (hall+1 = magnetic field CW), offset 0~5 steps |
| 6~11 | Offset (hall+1 = magnetic field CCW), offset 0~5 steps |
| 12 | Measured calibration CW |
| 13 | Measured calibration CCW |
| **14** | **Forced CW [sector+90°]** (closed-loop forward default) |
| **15** | **Forced CCW [sector-90°]** (closed-loop reverse default) |

## Hall Sensor Detection Method

### GPIO & Interrupt Configuration

Three Hall sensors on PA10 (U), PA9 (V), PA8 (W), configured as digital inputs with pull-up:

```
U: PA10 → EXTINT_CH10 → INT010_IRQn  (both-edge, HW filter DIV64 ~1.56 MHz)
V: PA9  → EXTINT_CH09 → INT009_IRQn  (both-edge, HW filter DIV64 ~1.56 MHz)
W: PA8  → EXTINT_CH08 → INT008_IRQn  (both-edge, HW filter DIV64 ~1.56 MHz)
```

Each ISR reads all 3 GPIOs to form a 3-bit state (0x01~0x06 are valid, 0x00/0x07 are fault).

### ISR Multi-Sample Debounce

PWM switching noise can couple onto Hall lines and cause false EXTINT triggers. Two layers of defense:

**Layer 1 — Hardware filter**: EXTINT filter ON with DIV64. PCLK1/64 ≈ 1.56 MHz sampling rate. Rejects glitches shorter than ~10 µs.

**Layer 2 — Software double-sample**: After EXTINT fires, read all 3 GPIOs twice with ~0.5 µs gap (100 NOPs @ 200 MHz). If the two reads disagree, the trigger is a PWM glitch → discard immediately without calling `GetDelta()`. This preserves the delta counter for the next legitimate transition.

```
hall_common_handler (ISR):
  1. read_hall_state_raw()  → state1
  2. delay ~0.5 µs
  3. read_hall_state_raw()  → state2
  4. state1 != state2 → return  (PWM glitch)
  5. state == last_hall_state → return  (no change)
  6. hall_to_step[state] == 0xFF → fault (000/111)
  7. direction check: diff != 1 and diff != 5 → return  (invalid jump, don't update last_step)
  8. NOW call GetDelta()  ← only valid transitions reach here
  9. interval < 50 µs → return  (too fast, noise)
 10. record pulse: interval, timestamp, pulse_counter++
 11. direction confirmation (3 consistent samples)
 12. on_step callback → Commutation_Step
```

### Critical Design Decision: GetDelta() Called Late

`Timer6_Timebase_GetDelta()` resets its internal counter on every call. If called during a noise event that is later rejected, the counter is reset and the NEXT legitimate transition measures from the noise event — causing a false short interval and incorrect RPM.

By placing `GetDelta()` AFTER all structural checks (steps 1-7 above), noise events never reset the counter. The interval always measures from the last VALID pulse.

### Direction Detection

```
diff = (current_step - last_step + 6) % 6

diff == 1 → tentative = FORWARD
diff == 5 → tentative = REVERSE
otherwise → invalid jump, return (do NOT update last_step)
```

Direction is confirmed after `DIR_CONFIRM_COUNT` (3) consecutive consistent direction samples. This prevents brief oscillation from toggling the reported direction.

On invalid jumps, `last_step` is NOT updated. This prevents PWM noise from corrupting the tracking state — a corrupted `last_step` would cause all subsequent legitimate transitions to be rejected as "invalid jumps."

### RPM: M-Method (Pulse Accumulation)

Instead of measuring time per individual pulse (T-method, noise-sensitive), RPM is calculated from accumulated pulses over a configurable time window:

```
hall_3ch_update (called from CommRunner_Update, ~1 kHz):

  // Accumulate pulses since last call
  delta = pulse_counter - last_pulse_count
  accum_pulses += delta
  last_pulse_count = pulse_counter

  // Two trigger conditions:
  if accum_pulses >= 6 AND elapsed >= 20 ms:
      → High-speed accurate update (at least 1 electrical revolution)
      RPM = accum × 60,000,000 / (elapsed × pole_pairs × 6)
      push to sliding-window filter (6 samples)
      reset accum + timer

  if elapsed >= 500 ms AND accum_pulses > 0:
      → Low-speed forced update (enough time, whatever pulses we have)
      RPM = accum × 60,000,000 / (elapsed × pole_pairs × 6)
      push to sliding-window filter
      reset accum + timer

  if elapsed >= 500 ms AND accum_pulses == 0:
      → Motor stopped
      RPM = 0, push to filter, reset accum + timer
```

**Filtering**: 6-sample moving average (`update_rpm_filter`). Exposed as `g_hall_rpm` volatile for Keil Watch.

### RPM Formula

```
RPM = pulses × 60,000,000 / (dt_microseconds × pole_pairs × 6)

Where:
  pulses         = accumulated hall transitions in the window
  dt_microseconds = elapsed time since last RPM update
  pole_pairs      = motor pole pairs (configurable, default 3)
  6               = steps per electrical revolution
  60,000,000      = microseconds per minute
```

### Flying Start

`hall_3ch_start_flying()` reads the current Hall state via double-sample (reuses `read_hall_state_raw()`), maps to step via table, and immediately enters `STATE_RUNNING` without alignment. This allows seamless transition from open-loop forced drive to closed-loop Hall-synchronized commutation.

```
hall_3ch_start_flying:
  1. read_hall_state_raw() → h1
  2. delay ~0.5 µs (100 NOPs)
  3. read_hall_state_raw() → h2
  4. h1 != h2 → fallback to state 0x00
  5. step = hall_to_step[hall_state]
  6. step == 0xFF → fallback to step 0
  7. state = STATE_RUNNING, last_step = step
  8. call on_step callback → immediate first commutation
```

### Stall Detection

In `hall_3ch_update`, if `last_pulse_time_us` exceeds `stall_timeout_ms` (default 500 ms) since the last valid Hall pulse, the motor is flagged as stalled and commutated to STOP.


## main.c Loop

```c
while (1) {
    App_Comm_Poll();                   // Modbus RTU communication

    // Keil Watch → CommRunner
    if (comm_mode != prev_mode)   CommRunner_SetMode(comm_mode);
    if (g_comm_duty_pct != prev)  CommRunner_SetDuty(g_comm_duty_pct);

    CommRunner_Update();               // Drive state machine

    // CommRunner → Keil Watch (stall/fault auto-stop)
    if (CommRunner_GetMode() != comm_mode) comm_mode = CommRunner_GetMode();
}
```
